# collab-richtext-go

一套多人实时协同的富文本编辑内核。多个参与者同时编辑同一份文档时，各端正文内容和格式最终一致，并能实时看到彼此的光标与选区。本地用回环传输即可复现乱序、重复、丢包与断线重连，不依赖外部服务。

## 核心特性

- **并发插入与删除**：基于 RGA（Replicated Growable Array）CRDT，操作到达顺序不同也能收敛到相同内容；重复投递幂等。
- **属性设置与取消**：Peritext 风格的区间标记（mark），支持加粗、斜体等任意属性；属性操作与文本增删并发时结果确定且可解释；被删除内容上的属性变化不牵连存活内容。
- **离线编辑与重新加入**：离线期间本地操作在恢复连接后补发并合并；落后的操作端通过版本向量按区间补齐缺失历史。
- **在线状态**：光标与选区位置实时广播；临时状态不写入文档历史、不进版本向量、不被快照持久化；异常掉线超时自动清理。
- **快照与历史压缩**：支持持久化文档状态并在重启后恢复；压缩掉不再被引用的墓碑字符，压缩后仍与持有完整历史的一端收敛。
- **本地回环传输**：内存通道模拟乱序、重复、丢包与断线重连；连接恢复后既不丢操作也不重复应用；超时与重试策略可配置。
- **确定性重放**：固定操作集合与固定随机种子下结果可复现；并发安全（通过 `-race` 检测）。

## 收敛规则

### 文本（RGA）

每个字符有唯一 ID `(clientID, clock)`，`clock` 是参与者本地单调递增的逻辑时钟。插入操作记录其左侧字符的 ID（`origin`）。

插入算法从 `origin` 出发向右扫描：

- 若下一节点与新节点同起点（`origin` 相同），ID 更大的排在前面（降序）；
- 若下一节点起点不同，仅当其起点排在 `origin` 之前时才越过它。

该规则保证同一组操作以任意顺序应用都收敛到同一链表。删除是幂等的墓碑标记，删除与插入满足交换律（删除可先于插入到达）。

### 每参与者因果顺序

版本向量（VV）记录每个参与者已观察到的最大时钟。为避免高时钟操作先到达时跳过低时钟操作（导致低时钟操作被误判为"已见"而永不应用），应用操作时要求：

```
op.ID.Clock == vv[op.ID.Client] + 1
```

否则操作暂存，待缺失操作到达后自动刷新。

### 属性（Mark）

属性操作是独立的 CRDT op，包含属性名、取值与区间锚点（start/end）。锚点引用字符 ID 并带偏向（Before/After）。

渲染时，每个存活字符位置上每个属性取覆盖它的标记中 ID 最大者（LWW），未被任何标记覆盖时取默认值 false。标记锚定到字符位置，因此在区间内插入文本时，新字符是否被覆盖取决于锚点偏向，行为确定。

## 在线状态生命周期

1. **加入**：参与者调用 `Join()`，广播 `MsgJoin`（含自身状态）。其他参与者收到后将其加入在线列表，并回发自己的状态与同步请求。
2. **更新**：光标/选区变化时调用 `UpdateCursor()`，广播 `MsgPresence`。
3. **离开**：调用 `Leave()`，广播 `MsgLeave`，其他参与者将其移出在线列表。
4. **异常掉线**：其他参与者通过 `CleanupStalePeers(timeout)` 清理超过 `timeout` 未活动的参与者。

在线状态是临时状态：不写入文档历史、不进版本向量、不被快照持久化。

## 可调参数

`TransportConfig`：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `LossRate` | 丢包率 [0,1] | 0.0 |
| `DuplicateRate` | 重复投递率 [0,1] | 0.0 |
| `ReorderWindow` | 乱序窗口（消息最大乱序步长，0 表示不乱序） | 0 |
| `ReconnectDelay` | 断线重连延迟 | 50ms |
| `AckTimeout` | 确认超时 | 200ms |
| `MaxRetries` | 最大重试次数 | 5 |
| `Seed` | 随机种子（确定性重放） | 42 |

`CleanupStalePeers(timeout)`：清理超过 `timeout` 未活动的参与者。

## 快照与历史压缩

- `Snapshot()`：生成当前文档的可持久化状态（字符、属性标记、版本向量）。
- `Restore(snap)`：从快照恢复文档状态。
- `Compact()`：移除不再被任何节点起点或属性锚点引用的墓碑字符。压缩后文档与仍持有完整历史的一端继续收敛。
- `SaveSnapshot(snap, path)` / `LoadSnapshot(path)`：JSON 格式持久化到文件。

## 并发安全

`Document` 用一把读写锁保护全部状态。本地读取（`Text`/`RichText`）与远端操作应用、快照写入同时发生时，读取方通过 `RLock` 获得一致性快照，不会读到半截状态，也不存在数据竞争。
